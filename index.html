Back up your Pakon scanner's calibration

Every Pakon F-135 and F-135+ carries a small memory chip holding data that is unique to that one scanner: its serial number, its motor speeds, and its colour matrices. If that chip fails there is nothing to download and no way to recreate it. This page reads it and gives you the files to keep. It reads only; it never writes to the scanner.

This browser can't talk to USB devices. Open this page in Chrome or Edge on a Mac or Linux computer. Safari and Firefox don't support WebUSB, and on Windows the Pakon driver keeps the scanner to itself (see the note at the bottom).

1. Plug in and power on the scanner, then connect

Turn the scanner on, wait for the lights to settle, then click Connect. Chrome will show a small window listing USB devices; choose the Pakon (0f05:f235 when freshly powered on).

2. Load the scanner's firmware

Happens automatically after Connect. The scanner keeps its working program in memory that is wiped every time it is switched off, so whatever software you use, this same load happens every time it powers on. It doesn't touch the memory chip we are backing up. When it finishes, the scanner disconnects and reconnects on its own; give it five seconds.

3. Read the chip

Click Read; Chrome shows the picker again (choose the Pakon, now 0f05:f135). Reading takes about ten seconds and uses the same two requests the original Kodak software uses at every launch.

What this page sends to your scanner, and what it doesn't


    
  
  • To load the firmware: the standard Cypress FX2 memory-load requests
  (0xA0, 0xA3) with Kodak's own firmware image for
  your scanner's revision, plus the loader's init (0xA4 with value
  0xA1). Every image is checked against a known SHA-256 before a byte
  is sent.
    • 
  
  • To read the chip: 0xA4 with value 0x00A5 (select the
  chip, read direction) then 0xA9 at increasing offsets, 32 bytes at
  a time. This is the sequence Kodak's own engine (TLB.dll) issues at every
  launch, taken from a capture of it.
    • 
  
  • Never: 0xA2 (the EEPROM write request), any other value on
  0xA4, or any command to the scanner's motor and light controllers.
  The page contains no code for any of those.
    • 
  
  • The page makes no network requests except loading its own files. Nothing
  you read leaves your computer.
    •

Windows: the Pakon driver claims the scanner, so Chrome can't
reach it without swapping the driver (Zadig/WinUSB), which stops the Pakon
software working until you swap back. If you have the Kodak software installed,
its own copy of most of this data is in the registry under
HKLM\Software\Pakon\TLB\ColorKodak; export that as a stop-gap.


Linux: works, but your user needs permission for the device
(a udev rule for vendor 0f05).
